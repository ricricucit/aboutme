# Repository Guidelines

## Project Structure & Module Organization

This is a dependency-free static site generated by `build.mjs` with Node.js 18 or newer. Localized content lives in `content/<lang>.json`; keep every translation aligned with the canonical `content/en.json` key structure. Standalone One Day posts belong in `content/oneday/YYYY-MM-DD-slug/<lang>.html`. Shared CSS, licensed fonts, and optimized images live under `src/`; files in `static/` are copied unchanged. Generated output goes to `dist/` and should not be edited directly. Lighthouse end-to-end checks are in `test/lighthouse.mjs`.

## Build, Test, and Development Commands

- `npm run dev` builds and serves the site at `http://localhost:5173`; each request rebuilds the project.
- `npm run build` creates a one-off production build in `dist/`.
- `npm test` builds, serves, and runs Lighthouse 12 in mobile and desktop modes. Chrome is required; `npx` fetches Lighthouse.
- `LH_PAGES=/,/fr/cv/ npm test` checks a custom page sample.

The project has no package dependencies, so contributors do not need `npm install`.

## Coding Style & Naming Conventions

Use ES modules and Node built-ins only. Follow the existing two-space JavaScript indentation and compact helper-function style in `build.mjs`. There is no linter; preserve nearby formatting and run the build to catch malformed content. Name language files with lowercase language codes (`content/it.json`) and post folders with an ISO date plus kebab-case slug. In CSS, reuse the four existing type-size tokens and `--rN` rhythm steps instead of adding ad hoc sizes or spacing.

## Testing Guidelines

Every change must keep the sampled pages at Lighthouse 100 in performance, accessibility, best practices, and SEO. Run `npm test` before opening a pull request. Reports are written to `.lighthouse/`. When changing localized content or routes, also build and inspect the affected pages in `dist/`.

## Commit & Pull Request Guidelines

Recent commits use concise, imperative subjects, often with a scope such as `docs:`, `test:`, or `content:`. Keep each commit focused. Pull requests should explain user-visible changes, list commands run, and link relevant issues. Include before/after screenshots for layout or visual changes, and call out any translation updates or Lighthouse exceptions.

## Security & Content Constraints

Do not add private CV data, external scripts, or new font weights. Maison Neue assets are licensed only for this site. Keep images optimized and prefer existing assets or inline SVG.
